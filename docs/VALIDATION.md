## 冻结软件评测

v0.1 冻结环境的结果：[交互报告](../results/v0.1.0/benchmark_venv_verified_002/report.html)、[机器可读汇总](../results/v0.1.0/benchmark_venv_verified_002/summary.json)、[45 个任务配置](../results/v0.1.0/benchmark_venv_verified_002/cases.json)。9 场景 × 5 seeds × 2 策略，共 **90 回合**。这轮没有训练模型，也未依据其测试失败调整基线或验收阈值。

| 场景 | 规则基线任务通过 | 解释 |
|---|---:|---|
| nominal | 5/5 | 完成全部流程 |
| noisy | 2/5 | 另 3 次最终图未达到重复性要求，退出 |
| drift | 5/5 | 测得不重复，退出 |
| double_tip | 1/5 | **4 次误接受**，一致的伪影可以通过数值门槛 |
| no_tunnel | 5/5 | 有限尝试后未建立隧穿 |
| current_spike | 5/5 | 测得过流并停止 |
| scan_timeout | 5/5 | 超时证据成立，停止 |
| flat | 5/5 | 缺乏纹理，正确拒绝 |
| stale_frame | 5/5 | 缓存/重复采集证据被拒绝 |

规则基线任务通过 **38/45（84.44%）**，Wilson 95% 区间约 **71.22%–92.25%**；随机基线 **5/45（11.11%）**。规则基线的 `workflow_success=11` 是数值流程完成次数，包含 4 次故障误接受，不能当作 11 次正确实验。10 个要求完成的任务实际完成 7 个；35 个要求拒绝的故障任务正确处理 31 个。两策略均无清理失败或执行器异常。

这些区间只描述构造任务集，不是实际仪器可靠性。`double_tip` 是方向相关的程序化重影挑战，不是真实双针尖数据。新策略可以在 `judge` 中同时给出数值 `label` 与独立 `diagnosis`；合成评测器可依据注入标签核对诊断，Demo 对科学诊断只保留“未验证假设”。

首轮冻结结果使用 Python 3.11 / NumPy 2.4.4。独立 `.venv` 使用 NumPy 2.4.6 重跑完全相同的 seeds，所有聚合成绩一致；运行时版本与源快照分别保存，没有覆盖首轮记录。这是环境复核，不是额外独立样本。
